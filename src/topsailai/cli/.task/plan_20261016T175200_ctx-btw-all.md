## Human requirement

> runtime scope 有一个 ctx.btw 指令，它只传递当前session+pid的信息。我希望加入 ctx.btw-all 指令，它会传递session对应的所有pids的信息。可以做到吗？适合做吗？如果可以，请实现。

Interpretation: broadcast the entered message to the injection queues for all discoverable live PIDs sharing the watched session identifier, not send a list of PID metadata. Preserve the current single-PID command.

- `topsailai_session_add_agent2llm_message.py::discover_jsonl_files` already enumerates immediate session/task stdout files and derives session-plus-PID injection paths. Without a PID it selects the whole session, but does not deduplicate identical injection paths or test liveness. Its main returns success if any write succeeds. ## Feasibility verdict

Feasible entirely inside the CLI workspace using existing injection file protocol. Enumerate immediate regular, non-symlink `.session.stdout` and `.task.stdout` evidence in the supplied runtime task directory; parse, require exact session equality, validate positive PIDs and deduplicate by `(session_id, integer PID)`. For each candidate derive exactly `{session_id}.{pid}.session.agent2llm_inject_messages.jsonl` under that same directory, validate evidence and liveness, validate the injection endpoint, then append using the public writer.

This is discoverable process coverage, not OS-wide process discovery: no descendant tree walk, lsof/fuser fallback, wildcard matching, other-session fallback or dependence on a potentially stale UI log-file list. A PID without matching stdout evidence cannot be discovered. A child process that does not read an injection queue cannot be made to consume it by this CLI change; queue success is not proof of consumption. Changing receivers is out of scope.

## Suitability verdict and boundaries

Appropriate as a separate explicit broadcast command for coordination or shared context across agents in one named session. Not appropriate as the new default for `/ctx.btw`, and not an exactly-once or atomic broadcast facility.

- Reject empty/unknown session identity, `(temp)` and literal `topsailai` before any write: independent temporary runs share that sentinel and must never be grouped.
- Require runtime scope; workspace/project/session/doc scopes must not execute this built-in. Non-interactive `topsailai runtime` stays single-target and must continue rejecting broadcast syntax.
- Broadcast includes the watched PID if eligible and other exact-session session/task PIDs. Do not collapse all task rows onto their parent; deduplicate actual child PID instead.
- Snapshot the candidate set once after message acquisition; new processes appearing later require another user command. Never rediscover to substitute for a failed target.
- Exited targets: explicitly skip, never create stale queues. Unknown/denied liveness: fail closed for that PID and report why. Other eligible PIDs may continue. Unsupported platforms must report inability to verify rather than treating unknown as alive; reuse the existing portable probe policy without introducing dependencies.
- Recheck the original evidence path and exact parsed identity plus PID liveness immediately before every append. If multiple evidence files share a PID, select deterministically with session stdout preferred, otherwise lexical task path; if selected evidence disappears, report it rather than switching to a newly discovered target.
- Require real task directory, regular non-symlink stdout evidence and validated non-symlink injection endpoint; permission/enumeration errors must be visible. Reuse `validate_runtime_endpoint` with `RuntimeTarget` evidence where applicable, but do not invoke the session-only revalidator for task evidence.
- Filenames/liveness assume trusted per-user task storage; they do not authenticate process identity or eliminate PID reuse and check/open races. Do not claim otherwise. Existing public writer also provides no hard write deadline.
- No automatic retries: interrupted/failed append can have uncertain delivery; repeated user invocations can duplicate context. Do not roll back completed writes or swallow KeyboardInterrupt/SystemExit.
- Broadcast can trigger conflicting work if the message is an imperative; documentation should recommend shared informational context rather than assuming coordinated execution.

## Delivery semantics

Use a compact typed result per PID containing PID, evidence path, status and diagnostic/cause, and an aggregate result with counts. Suggested statuses: queued, skipped_exited, skipped_unverifiable, failed_prewrite, delivery_unknown. Report the session and candidate count before delivery and one bounded diagnostic per PID without echoing message contents. No extra confirmation prompt is required: the explicitly named command is the broadcast opt-in.

Attempt each eligible snapshot PID at most once. Continue after ordinary per-target errors. Writer true means queued, not consumed. Writer false or exception means unconfirmed/possibly delivered, never retry automatically. Summary must distinguish queued, skipped, failed and uncertain counts. No matches or zero queued is not success. Any failed, uncertain or unverifiable target means incomplete broadcast even if some queues succeeded. Known exited skips may coexist with successful delivery to all eligible live PIDs, but must still be reported. Interrupted execution retains already printed outcomes and does not claim overall completion.

## Parsing and input contract

Syntax: `/ctx.btw-all [message...]`, with slashless spelling only if existing UI normalization supplies it. Match a complete command token, never a prefix: `/ctx.btw-all-extra` must not broadcast or fall back to single-target injection. The rest is the message, not a session/PID selector. Preserve multiline Unicode, quotes and shell metacharacters as message data; do not call shell/YAML execution. Empty body invokes the curses multiline provider or the legacy input collector; collect once for all PIDs. Cancel or whitespace-only input performs no target writes. Retain current EOF/Ctrl+D and Ctrl+C/Esc conventions; if reusing a collector, parameterize only its prompt without altering old behavior. Use the existing runtime 1 MiB UTF-8 message bound for the new command and reject invalid Unicode/oversize before enumeration/writes.

## Acceptance and verification checklist design

Before tests, create the execution checklist. Keep all fixtures, HOME overrides, pytest cache, bytecode, coverage and captured output under workspace `.tmp`; do not use the real agent task directory. Probe/writer injection must not mutate shared os module singletons.

- Two same-session live PIDs receive identical queued messages exactly once; different-session PID receives none. Include session plus multiple task logs for one PID and a task-only PID.
- Cover no matching stdout, missing/denied directory, malformed/nonpositive PID, unrelated stderr/legacy generic file, symlink stdout/directory/endpoint, temporary/empty ID and parser-supported dotted session exact matching; never guess unsupported task names.
- Dead, unknown and permission-denied probes get distinct visible outcomes. Process exit/evidence replacement between scan and append prevents that write. New PID after snapshot receives nothing.
- Writer true/false/exception and mixed outcomes demonstrate accurate summaries, continuation and no retries. Host interrupts propagate. Message content is never logged as an error diagnostic.
- Inline and multiline messages, Unicode, quotes, shell tokens, empty input, cancel, over-limit size and exact-token rejection are checked without executing shell content.
- Runtime-only completions/help and all fallback/startup command hints include the command. Non-runtime use and non-interactive broadcast stay rejected.
- Existing `/ctx.btw` still passes only the watched PID; `/send`, control, metadata and single-target non-interactive operations remain unchanged.
- Automated functional check: invoke shared interactive dispatcher with fixture stdout evidence, injected live probes and real public writer, then inspect exact JSONL records; verify unrelated queues untouched. This proves queueing, not live receiver consumption. If the core writer cannot import, report blocker rather than substituting a passing fake as integration evidence.
- Run focused new test files first, then affected streaming/help/completion suites and existing helper tests, then full `tests/unit/topsailai` regression. Tests must be colorless; record elapsed time, failures and skips. Aim above 93 percent unit coverage for the new broadcaster, rerun scoped coverage after final repairs.
- A real multi-agent consumption check is optional only with isolated available receiver environment and reproducible script; otherwise explicitly disclose queue-only evidence. It must not touch real sessions or imply consumption was proven.
