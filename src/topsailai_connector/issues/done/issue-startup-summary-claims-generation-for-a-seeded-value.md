# The startup summary claimed a generation for a seeded value

## Symptom

A build packaged with `PACKAGE_EMBED_IDENTITY=1` printed:

```
a new node id was generated by this start
a new credential was generated by this start
```

Both values came from the binary, not from a random generator. The message was
false for exactly the build whose operator most needs to know where the values came
from, because that operator chose them at packaging time and is reading the summary
to confirm the package adopted them.

## Root cause

`cmd/connector-node/main.go` printed a fixed string whenever the ensure function
reported `generated == true`. The flag means "this start wrote the file", which is
true for a seeded value as well as for a random one. The message named a mechanism
the flag does not describe.

## Detection gap

The wording was written when the only possible source was a random generator, so it
was accurate then. Adding a second source did not change the flag, and no test
asserted the wording against a seeded build. The defect was found by running the
packaged binary and reading its output, not by reading the diff.

## Fix

Both lines now say "written by this start", which is true for either source. The
`NewIdentity` doc comment was corrected for the same reason: it said "whether it was
generated by this start" and now says "whether this start wrote it", with the reason
stated.

Three assertions in `cmd/connector-node/main_test.go` and two in
`tests/integration/node_process_test.go` were updated to the new wording.

## Prevention

A message that claims provenance must be true for every path that reaches it. When a
value gains a second source, grep for the words that name the first source
(`generated`, `random`, `minted`) rather than only for the function that produces it.
